# Спецификация и концепция: SIA Simulation Workbench (v2 — Ревизия после аудита)

## 1. Главная цель и архитектурный принцип UI

**SIA Simulation Workbench** — это не просто кабина симулятора яхты, а **визуальный инструмент доказательства и исследования безопасности**:

> **«Вот что произошло (Ground Truth). Вот что увидели сенсоры (SensorFrame). Вот что понял SIA. Вот что он решил. Вот почему он спросил шкипера (Query Loop). И вот независимая оценка результата (Oracle / Evaluator).»**

```
                       SCENARIO
                          │
                          ▼
                    TIME / EVENTS
                          │
             ┌────────────┴────────────┐
             ▼                         ▼
       GROUND TRUTH               SENSOR FRAME
      "Что реально"               "Что видит SIA"
     [Лабораторный вид]          [Яхтенные приборы]
             │                         │
             │                         ▼
             │                     SIA CORE
             │                         │
             │                         ▼
             │                  DECISION / QUERY
             │                         │
             └────────────┬────────────┘
                          ▼
                     ORACLE / EVALUATOR
                          │
                          ▼
                        RESULT
```

## 2. Ключевые изменения и UX-принципы

### 1. Визуальное разделение «Что знает мир» и «Что видит SIA»
- **Левая панель (GROUND TRUTH):** Стилизована как строгий **лабораторный монитор физики**.
  - Черный моноширинный терминал с меткой `● NOT AVAILABLE TO SIA`.
  - Никаких «яхтенных приборов» здесь нет, чтобы не путать с бортовой панелью.
- **Центральная панель (SENSOR VIEW):** Настоящие **морские приборы Raymarine / B&G / Garmin**.
  - Только то, что поступает в `SensorFrame` (с учетом шума, задержек и выпадений).
  - Диагностический слой шума/задержек (`noise`, `bias`, `latency`) доступен по запросу в режиме Debug.

## 3. Детализация ключевых блоков

### А. Иерархия решений в SIA Panel
Вместо перегруженного списка параметров:
1. **Заголовок опасности и срочность:** `⚠ BROACH PRECURSOR | CRITICAL | TTE (Time to Event): 4.2s`.
2. **Главное решение доминирует (Primary Response):** Выделенная визуальная карточка с конкретным действием (`BEAR AWAY / Rudder -15°`, приоритет `0.95`).
3. **Альтернативы:** Компактные строки кандидатов (`2. EASE MAIN 0.85`, `3. PREPARE CREW 0.70`).
4. **Технические метаданные:** `Decision Latency: 240 ms`, ссылки на правила аудита.

### Б. Query Loop — Центральный элемент коллаборативного интеллекта
- **Принцип:** *SIA не фантазирует недостающий контекст — он спрашивает человека.*
- При отсутствии сенсоров шкотов/рифов SIA выдает лаконичный запрос с кнопками быстрого выбора в 1 клик.
- При ответе статус меняется на:
  > **`SIA: Context updated → Recalculated decision`**  
  *(Без оценочных суждений «точный совет», так как истинность оценивает только Оракул).*

### В. Timeline & Temporal Debugger
Многодорожечный таймлайн выполняет двойную функцию:
1. **Редактор сценария:** Визуальное размещение порывов (`GUST`), волн (`WAVE`), отказов приборов (`FAULT`).
2. **Временной отладчик (Temporal Debugger):** Перемещение курсора назад-вперед позволяет покадрово видеть:
   - В какой миллисекундах началась волна в Ground Truth.
   - С какой задержкой датчики отразили изменение в SensorFrame.
   - В какой именно момент сработал триггер детектора SIA.

### Г. Два режима отображения: Live vs Debug
- **Режим LIVE (Operation):** Минималистичный, контрастный морской вид для оценки ситуации и решений.
- **Режим DEBUG (Research):** Раскрывает сырые значения, задержки очередей, матрицы шумов, логику разрешения конфликтов (Conflict Resolution Notes) и панель Оракула/Оценщика.

## 4. Контур независимой оценки (Oracle / Evaluator Bar)

В нижней части экрана расположен статус независимого арбитража:
- **Oracle Ground-Truth Envelope:** Был ли нарушен физический предел безопасности (опрокидывание/нокдаун).
- **Latency Target:** Уложилась ли реакция СИА в допустимое окно времени ($\le 500\,\text{мс}$).
- **Objective Verdict:** Автоматический вердикт `PASS` / `FAIL`.
