# Спецификация и концепция: SIA Simulation Workbench (v2 — Ревизия после аудита)

## 1. Главная цель и архитектурный принцип UI

**SIA Simulation Workbench** — это не просто кабина симулятора яхты, а **визуальный инструмент доказательства и исследования безопасности**:

> **«Вот что произошло (Ground Truth). Вот что увидели сенсоры (SensorFrame). Вот что понял SIA. Вот что он решил. Вот почему он спросил шкипера (Query Loop). И вот независимая оценка результата (Oracle / Evaluator).»**

```
                       SCENARIO
                          │
                          ▼
                    TIME / EVENTS
                          │
             ┌────────────┴────────────┐
             ▼                         ▼
       GROUND TRUTH               SENSOR FRAME
      "Что реально"               "Что видит SIA"
     [Лабораторный вид]          [Яхтенные приборы]
             │                         │
             │                         ▼
             │                     SIA CORE
             │                         │
             │                         ▼
             │                  DECISION / QUERY
             │                         │
             └────────────┬────────────┘
                          ▼
                     ORACLE / EVALUATOR
                          │
                          ▼
                        RESULT
```

## 2. Ключевые изменения и UX-принципы

### 1. Визуальное разделение «Что знает мир» и «Что видит SIA»
- **Левая панель (GROUND TRUTH):** Стилизована как строгий **лабораторный монитор физики**.
  - Черный моноширинный терминал с меткой `● NOT AVAILABLE TO SIA`.
  - Никаких «яхтенных приборов» здесь нет, чтобы не путать с бортовой панелью.
- **Центральная панель (SENSOR VIEW):** Настоящие **морские приборы Raymarine / B&G / Garmin**.
  - Только то, что поступает в `SensorFrame` (с учетом шума, задержек и выпадений).
  - Диагностический слой шума/задержек (`noise`, `bias`, `latency`) доступен по запросу в режиме Debug.

## 3. Детализация ключевых блоков

### А. World Presets & Environment (Колонка 1, Слева вверху)
1. **Быстрый выбор 4 погодных пресетов:** `Harbour` (4 kt), `Cruise` (13 kt), `Fresh` (21 kt), `Gale` (28 kt).
2. **Параметры мира:** Настройка длительности симуляции (от 5 до 120 с) и PRNG Seed для побитовой воспроизводимости.

### Б. Ground Truth Physics Lab (Колонка 1, Слева по центру)
1. **Лабораторный монитор физической реальности:** Полная телеметрия гидродинамики и среды ($TWS$, $TWD$, $H_s$, $T_p$, истинный крен Roll, дифферент Pitch, истинная скорость SOG, угол пера руля).
2. **Индикатор срыва руля (`RUDDER HYDRO LOSS`):** Мониторинг процента гидродинамической потери эффективности пера руля при крене и аэрации.
3. **Маркировка изоляции:** Яркая индикация `● NOT AVAILABLE TO SIA` (подтверждение соблюдения архитектурного инварианта Hard Boundary INV-01/02).

### В. Vessel Presets & Sail Rig Configuration (Колонка 2, По центру над Marine Console)
1. **Каталог судов (Vessel Presets):**
   - **`Beneteau Oceanis 45`** (Основной современный круизер): $LOA = 13.94\text{ м}$, $Beam = 4.50\text{ м}$, $Mass = 10550\text{ кг}$, $S = 100\text{ м}^2$, $H_{\text{mast}} = 19.5\text{ м}$, $GM = 1.35\text{ м}$.
   - **`IOR Classic 34ft`** (Классический монокорпус 10.5м): $LOA = 10.50\text{ м}$, $Beam = 3.40\text{ м}$, $Mass = 5200\text{ кг}$, $S = 65\text{ м}^2$, $H_{\text{mast}} = 14.2\text{ м}$, $GM = 1.10\text{ м}$.
2. **Конфигурация парусного вооружения (Sail Plan):**
   - ⛵ **`CODE_ZERO` (130%)**: Легкий полноразмерный геннакер/код зеро для максимальной тяги на попутных курсах ($C_T \times 1.3$).
   - ⛵ **`FULL_MAIN` (100%)**: Полный рабочий парусный гардероб.
   - ⛵ **`REEF_1` (75%)**: Первый риф для условий свежего ветра.
   - ⛵ **`REEF_2` (50%)**: Второй риф для тяжелой штормовой погоды.
   - ⛵ **`STORM_JIB` (25%)**: Штормовой стаксель.
   - ⛵ **`BARE_POLES` (0%)**: Без парусов (дрейф под рангоутом).
3. **Прямое влияние на 4-DOF динамику:** Расчет сил в `sail_forces()` динамически масштабирует силу тяги, лобовое сопротивление и кренящее плечо относительно мачты и геометрии выбранного судна.

### Г. Иерархия решений в SIA Panel (Справа вверху)
Вместо перегруженного списка параметров:
1. **Непрерывный мониторинг и номинальный режим:** В отсутствие опасности SIA Panel четко отображает активный статус мониторинга: `STATUS: NOMINAL (MONITORING)` / `ADVISORY: MAINTAIN HEADING, OPTIMAL TRIM` с индикаторами риска и уверенности, предотвращая эффект «пустого/неработающего» экрана.
2. **Заголовок опасности и срочность:** При превышении порогов (`roll > 20°`, `yaw_rate > 1.5°/s` или удар волны/слеминг) мгновенно активируется контрастный заголовок: `⚠ BROACH PRECURSOR | CRITICAL` / `⚠ SLAMMING HAZARD`.
3. **Главное решение доминирует (Primary Response):** Выделенная визуальная карточка с конкретным действием (`REDUCE SAIL / DEPOWER 30%`, `COUNTER-RUDDER -20°`, `BEAR AWAY`, приоритет `0.95`).
4. **Альтернативы:** Компактные строки кандидатов (`2. EASE MAIN 0.85`, `3. PREPARE CREW 0.70`).
5. **Технические метаданные:** `Decision Latency: 240 ms`, ссылки на сработавшие правила.

### Д. Query Loop — Центральный элемент коллаборативного интеллекта (По центру вверху)
- **Принцип:** *SIA не фантазирует недостающий контекст — он спрашивает человека.*
- При отсутствии сенсоров шкотов/рифов SIA выдает лаконичный запрос с кнопками быстрого выбора в 1 клик.
- При ответе статус меняется на:
  > **`SIA: Context updated → Recalculated decision`**  
  *(Без оценочных суждений «точный совет», так как истинность оценивает только Оракул).*

### Е. Морская консоль инструментов (Marine Console 6-Dial Suite)
В центральной зоне консоли размещены 6 аутентичных приборов морского стандарта (Raymarine / B&G):
1. **Apparent Wind (AWA / AWS):** Роза ветров вымпельного ветра, сектора левого/правого галса, скорость ветра в узлах (`kt`).
2. **Heel Inclinometer (Бортовая качка / Крен):** Инклинометр крена с силуэтом яхты, шкалой $\pm 45^\circ$, цветовыми зонами безопасности (зеленая $\le 18^\circ$, желтая $18^\circ \dots 25^\circ$, красная $> 25^\circ$).
3. **Pitch Inclinometer / Trim (Килевая качка / Дифферент):** Прибор дифферента с продольным силуэтом яхты (нос вверх/вниз $\pm 15^\circ/\pm 30^\circ$) и отображением угловой скорости килевой качки (`Pitch Rate °/s`).
4. **Navigation (SOG / COG):** Компасная роза курса и скорости относительно грунта.
5. **Heave & Vertical Acceleration (Вертикальная качка):** Индикатор вертикального смещения ($z$ в метрах) и вертикального ускорения ($a_z$ в $\text{m/s}^2$ и $g$-force) с динамическими порогами перегрузки.
6. **Slamming & Hull Shock (Индикатор слеминга):** Прибор гидродинамических ударов волн о корпус, шкала пиковой силы удара ($\text{kN}$), счетчик ударов и пульсирующий световой индикатор при детектировании слеминга.

### Ж. Timeline, Zoom & Event Builder (Интерактивный таймлайн снизу)
Многодорожечный таймлайн выполняет три ключевые функции:
1. **Интерактивный конструктор сценариев (Event Placement):**
   - Палитра инструментов на панели таймлайна: `[+ Wind Gust]` (порыв ветра), `[+ Wave Slam]` (удар волны/слеминг), `[+ Sensor Fault]` (отказ датчика IMU/GPS/Wind).
   - Клик по дорожке таймлайна размещает выбранное событие в указанную миллисекунду.
   - Перетаскивание маркеров событий (drag handles) вдоль дорожки для изменения времени начала.
   - Инспектор параметров события (всплывающее окно) для настройки длительности, амплитуды или удаления.
2. **Масштабирование (Zoom & Pan):**
   - Кнопки зума `[ + ]`, `[ − ]`, `[ 1x ]` и зум колесом мыши от 1.0x до 10.0x.
   - Горизонтальное панорамирование (pan/scroll) при увеличении для точного покадрового анализа 100 Гц микро-шагов.
   - Адаптивная временная шкала с субсекундными делениями.
3. **Скруббер времени и воспроизведение:** Плавный Play/Pause, покадровый переход, интерактивное позиционирование курсора времени симуляции.

### З. Два режима отображения: Live vs Debug
- **Режим LIVE (Operation):** Минималистичный, высококонтрастный морской вид для оценки ситуации и рекомендаций.
- **Режим DEBUG (Research):** Раскрывает сырые значения, задержки очередей, матрицы шумов, логику разрешения конфликтов (Conflict Resolution Notes) и панель Оракула/Оценщика.

## 4. Контур независимой оценки (Oracle / Evaluator Bar)

В правой нижней части экрана расположен статус независимого арбитража:
- **Oracle Ground-Truth Envelope:** Был ли нарушен физический предел безопасности (опрокидывание/нокдаун/брочинг).
- **Latency Target:** Уложилась ли реакция СИА в допустимое окно времени ($\le 500\,\text{мс}$).
- **Objective Verdict:** Автоматический вердикт `PASS` / `FAIL`.
