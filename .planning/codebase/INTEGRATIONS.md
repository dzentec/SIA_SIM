# External Integrations & Boundaries

**Analysis Date:** 2026-09-17

## Overview

SIA Simulation is designed as a standalone, hermetic, and deterministic testbed with strict isolation boundaries.

---

## Internal Boundaries & Protocols

### 1. SIA Core Boundary Protocol (`SIACore`)
- **Location:** `src/sia_sim/sia/protocol.py`
- **Isolation Rule:** SIA Core receives ONLY `SensorFrame`. It has zero access to:
  - `GroundTruthFrame`
  - `WorldState`
  - Dynamics / Physics equations
  - Oracle / Evaluation internals
- **Enforcement:** Enforced at runtime and verified by AST static analysis tests (`tests/unit/test_sia_boundary.py`).

### 2. Physical Safety Oracle Boundary (`PhysicalOracle`)
- **Location:** `src/sia_sim/evaluator/oracle.py`
- **Role:** Accesses ground truth to independently compute true safety envelopes, hazard onset, and recovery constraints without communicating with SIA Core during execution.

### 3. Run Recorder Boundary (`RunRecorder`)
- **Location:** `src/sia_sim/recorder/run_recorder.py`
- **Role:** Synchronously records three isolated telemetry streams into Polars DataFrames and Parquet:
  - `ground_truth_df`
  - `sensors_df`
  - `decisions_df`

## Network & Transport Interfaces

### 1. Local Workbench HTTP / REST API
- **Location:** `src/sia_sim/workbench/server.py`
- **Endpoints:**
  - `GET /` — Night bridge cockpit static single-page app
  - `GET /api/scenarios` — Available simulation scenarios list
  - `POST /api/run` — Trigger simulation run with custom parameters
  - `GET /api/vessels` — Vessel hydrodynamic and rig presets

### 2. Workbench WebSocket Telemetry Stream
- **Endpoint:** `WS /ws/telemetry`
- **Protocol:** JSON messages at 100 Hz (or synchronized playback speed) streaming `SensorFrame`, `GroundTruthFrame`, and `DecisionPayload` to browser dials.

## External Data Formats

- **Parquet / Arrow (`.parquet`):** Standard telemetry and replay storage.
- **JSON / JSON-Lines (`.json`, `.jsonl`):** Scenario specifications, decision logs, and evaluation reports.
