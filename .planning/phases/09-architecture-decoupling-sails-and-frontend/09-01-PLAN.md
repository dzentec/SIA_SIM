# Plan 09-01: Workbench Frontend Modularization (ES Modules)

## Objective
Decompose the monolithic `app.js` (~1100 lines) into focused, single-responsibility browser ES modules (`state.js`, `playback.js`, `modals.js`, `app.js`) while maintaining zero-build simplicity, 60 FPS Canvas rendering, and all interactive features.

## Tasks

### Task 1: Create State Management Module (`state.js`)
- Isolate `AppState` object with default parameters (scenarioId, seed, durationS, imuRate, vesselPreset, sailPlan, playback status, customWorld, customVessel).
- Provide clean state reset and subscription helper functions.

### Task 2: Create Playback Controller Module (`playback.js`)
- Encapsulate `playSimulation()`, `pauseSimulation()`, `stepSimulation()`, `scrubToTime()`, `stopLivingSeaToZero()`, `renderAtTime()`, and `renderZeroState()`.
- Maintain `requestAnimationFrame` loop, timing calculation, linear interpolation (`lerp`), and dial canvas update invocations.

### Task 3: Create Modals Controller Module (`modals.js`)
- Encapsulate Custom World Preset modal open/close/apply logic.
- Encapsulate Custom Vessel & Sail Inventory modal open/close/apply logic.
- Encapsulate Scenario Event Inspector modal open/close/save/delete logic.

### Task 4: Refactor `app.js` to Orchestrator Entry Point & Update `index.html`
- Wire event listeners, DOM bindings, and `/api/run` network calls using the modular components.
- Update script tags in `index.html` with modular script imports.

## Verification
- `uv run pytest tests/unit/test_workbench_integration.py` passes.
- Launch `uv run sia-sim --workbench --port 8080` and verify dials, timeline, query loop, and modals work seamlessly.
