# Plan 11-03: EnvironmentProvider Abstraction, Dead Reckoning & Simulation Engine Integration

## Objective
Decouple environmental generation in `WorldModel` using the `EnvironmentProvider` protocol, implement `SyntheticEnvironmentProvider` and `RealGeoEnvironmentProvider`, support dead reckoning $(lat, lon)$ coordinate evolution, and integrate CLI switches (`--real-geo`, `--lat`, `--lon`, `--offline-geo`) with snapshot-based test reproducibility.

## Tasks

### Task 1: Define `EnvironmentProvider` Protocol & Providers (`src/sia_sim/physics/environment.py`)
- Define `EnvironmentProvider` Python Protocol:
  ```python
  class EnvironmentProvider(Protocol):
      def get_wind(self, sim_time_ms: int, lat: float, lon: float) -> WindVector: ...
      def get_waves(self, sim_time_ms: int, lat: float, lon: float) -> WaveState: ...
      def get_current(self, sim_time_ms: int, lat: float, lon: float) -> CurrentVector: ...
      def get_depth_m(self, lat: float, lon: float) -> float | None: ...
      def get_nearest_hazard_nm(self, lat: float, lon: float) -> float | None: ...
  ```
- Implement `SyntheticEnvironmentProvider` wrapping analytical `WindModel`, `WaveModel`, and `CurrentModel`.
- Implement `RealGeoEnvironmentProvider` integrating `FrameAssembler` / DAE pipelines with spatial caching and temporal wind interpolation.

### Task 2: Refactor `WorldModel` & Vessel Dead Reckoning (`src/sia_sim/physics/world.py`)
- Refactor `WorldModel` to accept any `EnvironmentProvider`.
- Implement geographic dead reckoning in simulation step:
  - Track vessel position $(\text{lat}(t), \text{lon}(t))$ from initial coordinates.
  - Update coordinates each 10 ms tick based on surge/sway velocities $(u, v)$ and heading $\psi$:
    $$\Delta x = (u \cos \psi - v \sin \psi) \cdot \Delta t, \quad \Delta y = (u \sin \psi + v \cos \psi) \cdot \Delta t$$
    $$\Delta \text{lat} = \frac{\Delta y}{111\,139}, \quad \Delta \text{lon} = \frac{\Delta x}{111\,139 \cdot \cos(\text{lat})}$$
- Feed instantaneous true depth and hazard distance into `GroundTruthFrame` and virtual sensor models (depth sounder, GPS).

### Task 3: Scenario Contract & CLI Integration (`scenario.py`, `runner.py`, `cli.py`)
- Extend `Scenario` schema with optional `env_mode` (`synthetic` vs `real_geo`) and `real_geo_config` (start lat/lon, data source preferences, snapshot file).
- Update CLI parser to accept:
  - `--real-geo`: switch to real-world marine data mode.
  - `--lat <float>`, `--lon <float>`: starting geographic coordinates.
  - `--offline-geo`: force offline GRIB2/GEBCO/S-57 mode without network calls.
  - `--snapshot-save <path>`, `--snapshot-load <path>`: freeze/replay environment frames for bit-for-bit test repeatability.

### Task 4: Integration Verification Tests
- Test that `SyntheticEnvironmentProvider` reproduces identical results to baseline `WorldModel` (zero regression).
- Test `RealGeoEnvironmentProvider` with offline fixtures (mock GRIB2, GEBCO crop, S-57 cell).
- Verify hard boundary: ensure `SIACore` receives strictly standard `SensorFrame` regardless of the active environment provider.
- Test determinism: verify that a frozen snapshot run produces bit-identical telemetry traces across repeated executions.
